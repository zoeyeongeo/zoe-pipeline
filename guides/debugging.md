# 디버깅 절차

출처: 모험가 RPG `Assets/Code/CLAUDE.md` 디버깅 절차 (0.3.0 이식)

1. **증상 확정** — 무엇이 기대와 다른지 한 줄로. 재현 조건(씬, 캐릭터, 입력)을 같이 적는다. 재현이 안 되면 재현부터.
2. **근거 수집** — 콘솔(`unity command console`), `Logs/`, IDE 문제 목록(Rider MCP), CLI로 읽은 컴포넌트·SO 값. 추측 전에 실제 값을 본다. **인스펙터 직렬화 값을 먼저 의심한다** (코드 기본값을 덮는다).
3. **가설 하나** — `파일:줄` + 심볼로 지목하고 왜 그 증상을 만드는지 설명한다.
4. **검증은 한 번에 하나** — 한 곳만 바꿔 다시 돌린다. 안 되면 가설을 버리고 2번으로.
5. **수정 후 확인** — 1의 재현 조건으로 사라졌는지 확인하고 결과를 보여 준다 (W-008).

- learn 모드: 고치는 건 사용자. 원인이 확정되면 고치는 방향(무엇을·왜·어떤 API)만 준다. 임시 디버그 로그도 "어느 함수에 무엇을 찍을지"만 알려 주고 사용자가 넣는다. 확인 후 바로 지운다 (C-015).
- 설명은 증상 → 원인 → 고치는 법 순서. "해당 부분" 대신 파일명과 심볼명.

## 유니티에서 자주 나오는 함정

- 인스펙터 직렬화 값이 코드 기본값을 덮는다
- `ScriptableObject`의 런타임 변경은 에디터에서 에셋에 남는다
- 리컴파일 후 static 상태가 초기화된다
- 직렬화 필드명 변경 시 값 유실 (C-005)
- 이벤트 해제 누락 (C-004)
- 애니메이터 파라미터 이름 오타 — 문자열 접근 시 조용히 실패 (C-020)

프로젝트 고유의 "자주 나오는 원인"(초기화 순서 등)은 각 프로젝트 CLAUDE.md에 둔다.
