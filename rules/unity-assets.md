# Unity 에셋 작업 규칙 (A)

> 에셋 작업(SO 생성, 프리팹 조립, 인스펙터 연결)은 learn/build 모드와 무관하게 AI가 맡는다. 프로젝트 고유 금지 사항·관례는 프로젝트 CLAUDE.md를 따른다.

### A-001 수단 순서
- 심각도: SHOULD
- 규칙: Unity CLI 내장 명령 → CLI eval 또는 MCP → (사용자 승인 후) 에디터 스크립트·YAML 일괄 편집 순으로 쓴다
- 이유: 뒤로 갈수록 강력하지만 실수의 영향 범위가 크다
- 강제: 문서
- 예외: 없음

### A-002 반복 작업은 1~2개 먼저
- 심각도: SHOULD
- 규칙: 같은 에셋 작업을 여러 개 할 때는 1~2개를 먼저 만들어 보여 주고 승인 후 나머지를 한다
- 이유: 틀린 패턴이 수십 개로 복제되는 것을 막는다
- 강제: 문서
- 예외: 사용자가 전체 진행을 미리 승인한 경우

### A-003 바꾼 에셋 목록 보고
- 심각도: MUST
- 규칙: 작업이 끝나면 생성·수정·삭제한 에셋 경로를 목록으로 보고한다
- 이유: 에셋 변경은 diff로 읽기 어렵다. 목록이 범위 검사(W-006)의 근거가 된다
- 강제: 문서
- 예외: 없음

### A-004 .meta를 직접 지우거나 만들지 않는다
- 심각도: MUST
- 규칙: .meta 파일을 손으로 삭제·생성·GUID 수정하지 않는다. 에셋 이동·이름 변경은 Unity(CLI/에디터)를 통해 한다
- 이유: GUID가 바뀌면 그 에셋을 참조하던 모든 연결이 조용히 끊긴다
- 강제: 문서
- 예외: 없음
- 출처: 0.1.0 초안 제안 (승인 필요)
